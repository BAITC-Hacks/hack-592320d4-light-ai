# Хакатон: два разминочных кейса

Python 3.8+, только стандартная библиотека — ничего ставить не нужно.

## 1. Классификатор обращений

```bash
python3 classify.py              # читает messages.txt
python3 classify.py other.txt    # или любой файл: одно обращение на строку
```

Для каждого обращения из `messages.txt` скрипт печатает категорию
(справка / жалоба / другое) и черновик ответа на русском.

**Как устроено.** Только правила, без LLM (нет ключей, ответ мгновенный и одинаковый
при каждом запуске):

1. **Темы** (`TOPICS`) — столовая, Wi‑Fi, справка, парковка, консультация. Если
   совпала основа слова, берём категорию и готовый черновик. Жалобы проверяются первыми,
   поэтому «Почему опять нет интернета?» — это жалоба, хотя сообщение в форме вопроса.
2. **Запасной вариант** для незнакомых тем: слова-сигналы проблемы («не работает»,
   «пропал», «сломался»…) → жалоба; вопрос (`?`, «как», «где»…) → справка; иначе → другое.
   Черновик в этом случае берётся из общего шаблона категории.

Текст нормализуется: регистр, `ё → е`, разные дефисы (в `Wi‑Fi` из задания
стоит неразрывный дефис U+2011).

**Результат:** справка — 2 (справка об учёбе, парковка), жалоба — 2 (столовая, Wi‑Fi),
другое — 1 (запись на консультацию). Консультацию относим к «другому»: это запрос
на действие, а не вопрос и не жалоба.

## 2. Фильтр шума в событиях

```bash
python3 filter_events.py              # читает events.json
```

`events.json`:

```json
[
  {"event": "disk 90%", "level": "critical"},
  {"event": "user login", "level": "info"},
  {"event": "cpu 40%", "level": "info"},
  {"event": "payment failed", "level": "critical"},
  {"event": "heartbeat", "level": "info"},
  {"event": "db timeout", "level": "critical"},
  {"event": "cache miss", "level": "warn"},
  {"event": "deploy ok", "level": "info"}
]
```

Обычный filter по полю `level`, без агентов и тулов. Вывод:

```
[critical] disk 90%
[critical] payment failed
[critical] db timeout
критичных 3
```
